# 夜間の一括（063）の前の通し

API で流す前に、Claude を呼ぶところだけを claude -p（サブスクリプション）に差し替えて、同じプログラムを通しで流した。差し替えたのは API を呼ぶところだけで、ほかはそのままにしたので、プロンプトの出来だけでなく、プログラムそのものの不具合（答えを読み取れない・再開でずれる・ページが足りない など）も一緒に見つかる。会話の中の Claude に作業を代わりにやらせると、プログラムを通らないので、こうした不具合は見つからない。サブスクリプションの中で回したので、API の費用を使わずに直してから本番を流せる。
この通しで 8 件見つかり、3 件を直した。

## 流したもの（2026-11-05）

- 流れ: 仕分け → 取り出し（v2 の指示・深さ high）→ 角度と人形の動き → 言葉の欄 → 確かめる AI。モデルと深さは API の設定のまま
- 書き込み先: 手元の D1（会社のテナント）。本番の D1 には書いていない
- 仕分けは Managed Agents の代わりに、同じ指示を claude -p で 1 ページずつ呼んだ。Claude 以外の外のサービスを呼ぶ段は無いので、ダミーにした段は無い
- 同時に流したのは 4 本（仕分けはページの範囲で 4 つ、下書きは「する」のページを 4 組に分けた）
- 下書きを 20 枚ほど作ったところで 4 本ともわざと止め、同じ回で再開した
- 命令: `scripts/night-sort.ts manual --run <回> --pages <範囲> --sub`、`scripts/night-draft.ts --sort-run <仕分けの回> --run <回> --sub --shard <i>/4 --max 30`、数えるのは `scripts/night-draft-check.ts --run <回>`

- 足りないページ: 0（「する」の 62 ページ全部で決まりが 1 つ以上取れた）

## 分かったこと: 試す資料から例を取らない

- 2 周目の選ぶ段の指示には、分けの例として、試していた資料の決まりや当日のカードとほぼ同じ中身が入っていた。8 字続く重なりは無かったが、答えに直結する例が入っていると、赤が減った分のどこまでが本当の力か分からない
- 例を外し、分けの定義だけにした（`eval/prompts/pick_v1.txt`）。分けの定義の言い回しが取り出しの決まりと 8 字重なったので、それも言い換えた
- 漏れの検査（`scripts/leak-check.ts`）を、選ぶ段と取り出しの両方にかける。相手は、資料から取り出した決まり（1・2 周目と 062）・当日のカードの表・確認の項目（調整用 20・確認用 10）
  - 選ぶ段 v1: 重なり 0
  - 取り出し v2: 取り出しの決まりと 13・調整用と 3・確認用と 1。どれも中身の漏れではない。取り出しの決まりとの重なりは、v2 が書かせる決まり文句（「点検表の項目を 1 つずつ確かめて ✓ を付ける」）を取り出した側が写したもの。調整用と確認用との重なりは、v2 が型の例として挙げた法令の言い回し（「〜させなければならない」）。確認用の重なりがこの言い回しから来ることは、言い回しだけのファイルに検査をかけて確かめた（確認用の中身は見ていない）
