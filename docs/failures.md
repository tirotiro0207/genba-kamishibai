## 4. 11/6 の試しで失われた答え

- 答えが記録にあるのは 14 人のうち 9 人。① は 18 件 / 28 件、② は 48 件 / 112 件で、足りないのは最大 74 件
- 9:00〜9:55 に記録アプリが返した応答の数（出どころ: Cloudflare の workersInvocationsAdaptive。5 分ごとの、応答の番号ごとの件数。どの口へのどんな中身の送信かは出ない）:
  - 保存できた（201）65 件
  - はじいた（409: もう済んでいる）10 件
  - 入れなかった（401 が 27 件・403 が 14 件）
- 409 の 10 件は中身ごと失われた。画面は 409 を「前に送った答えがもう届いている」とみなし、端末に置いた答えを消す作りだったため。前の人の ID のまま次の人が送ると、この形で跡を残さずに消える
- 足りない最大 74 件のうち、約 64 件はサーバーに保存されていない（74 件から 409 の 10 件を引いた数）。401・403 で入れなかった送信は、画面が端末の中に置いたまま送り直す作りなので、その端末のブラウザに残っていることがある（応答の件数は送り直しも数えるので、答えの数とは一致しない）
- 仕組みの穴（直すまで残す）:
  - サーバーは、送られた参加者の ID と、入ったときの ID を突き合わせていなかった（ID は画面の URL から送る）
  - 409 を「届いた」とみなす扱いが、「済んだ人の ID で送られた別の人の答え」と区別できなかった
  - Workers のログを残す設定にしていなかったので、はじいた送信の中身は後から追えない
- 数え方では、答えの無い人の分を推し量って入れない（`docs/fieldday-2026-11-06-participants.md`）
