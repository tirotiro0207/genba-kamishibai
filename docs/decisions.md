## 2026-11-02 技術と置き場（000）

1 つの TypeScript のリポジトリにまとめ、公開の置き場は Cloudflare にする。会社のテナントの資料は外に出さず、重い処理は手元のスクリプトで行う。

| 項目 | 選んだもの | 理由 |
|---|---|---|
| 画面 | React と Vite（TypeScript）。1 枚の画面のアプリ | カードの紙芝居・枠を描く・指の署名など、画面の中で動くものが多い。ビルドすると静的なファイルになり、サーバーと同じ置き場から出せる |
| サーバー | Cloudflare Workers と Hono | 公開 URL・テナントごとの PIN・費用の上限を 1 か所で持てる。画面と同じ 1 回のデプロイで出せる。待ち時間が短く、使わない時間の費用がかからない |
| DB | Cloudflare D1（SQLite）。マイグレーションは wrangler | Workers からそのまま使える。テストは Workers のテストの道具で、テストごとに別の DB を作れる。追記だけの記録とハッシュの連鎖は SQL の表で足りる |
| 置き場 | Cloudflare R2。テナントごとに鍵の頭を分け、公開しない | 会社のテナントの資料・ページの画像を非公開で置ける。公開デモは架空の会社のテナントだけを読む。録画はリポジトリの外のフォルダ（環境変数で渡す） |
| PDF の処理 | mupdf（公式の WebAssembly 版）を手元の Node のスクリプトで使う | ページの画像と、行の位置付きの文字を取れる。会社の資料は手元で処理し、結果だけをテナントの置き場に入れる。Workers の上では重い処理をしない |
| PNG の処理 | 絵は自前のコードで SVG に描き、resvg で PNG にする（手元とテストは resvg-js、Workers は resvg-wasm） | 同じ SVG から同じ PNG ができる。画像を作るモデルを使わないので、部品と経路を残せる |
| 署名パッド | 自前の canvas と Pointer Events。パソコンは名前の印を SVG で描く | 指・ペン・マウスを同じ作りで受けられ、数十行で済む。外のライブラリに頼らず、線を SVG のパスとして保存し、ハッシュを取れる |

## 2026-11-02 取り出しの採点の照合のしかた（003a）

- 正解と答えの照合は **AI の判定**（`claude-sonnet-5-5`・effort low）にする。文字の一致にしないのは、同じ決まりでも言い方が大きく変わるため
- AI は「組にする」ことと、組ごとの判定（同じ・言い方の違い・危ない読み違い）と、危ない取り出しすぎの番号だけを返す。漏れ・取り出しすぎ・危ない読み違いの数は、コードが機械的に数える
- 判定の答えは、番号の範囲と「同じものを 2 回組にしない」をコードで確かめる
- 004 の最初の実行で、判定の AI が同じ答えを 2 回組にした。採点を止めるのをやめ、範囲の外と 2 回目の組を落として先へ進み、落とした数を履歴の「判定の直し」の列に残す（止めると、1 件の崩れで 20 項目ぶんの費用が無駄になるため）

## 2026-11-02 1 日目の仮の流れと土台（004〜012）

- **仮の姿勢の形**: 人物は 1〜2 人、関節は 10 か所の角度（度）、小物は 24 種から 8 つまで。モデルには構造だけの JSON Schema を渡し、角度・位置・大きさの範囲はコードで確かめる（Schema の数の範囲の指定に頼らない）。正式な骨格は 015 で作り直す
- **仮の人形の SVG**: 図形の要素（rect・line・circle・ellipse・polygon・polyline・path）だけを使い、数は小数 1 桁に丸める。文字・title・id を入れないので、絵から意味の手がかりが漏れない
- **PNG**: resvg-js で 768 px・白い背景にし、IHDR・PLTE・tRNS・IDAT・IEND 以外の塊を落とす。文字の塊（tEXt など）が残らず、どの環境でも同じバイト列になる
- **確かめる AI**: 「絵を読む」と「決まりと照合する」を別の呼び出しに分ける。読む側には決まりの文を渡さない。赤（60 点未満か危ない読み違い）なら、読み違えた中身と採点の理由を角度の係に渡して 1 回だけ作り直す
- **テナント**: 練習用と架空の会社は最初から作り、会社のテナントは PIN と一緒に作る。PIN は PBKDF2（10 万回・塩 16 バイト）のハッシュだけを持つ。入ったしるしは「テナント・期限」に HMAC で署名した文字列で、別のテナントでは通らない。どの読み書きも tenant_id で絞る
- **回答の記録**: 答えの表は追記だけ。書き換えと消すことは、サーバーが 405 で断り、DB のトリガーでも断る（二重の守り）。見せたもの（カードか文）は答える側に選ばせず、割り当てから決める。消す決まりは 025b
- **順番の乱数**: 種（16 桁の 16 進）を回ごとに残し、同じ種から同じ割り当てを作る（FNV-1a と mulberry32）。カードが先の人と文が先の人を半分ずつにし、項目 B は項目 A の逆の順番にする
- **録画**: Playwright で毎回録画し、置き場所は環境変数 RECORD_DIR（無ければリポジトリの private/rec）。録画のテストは手元の Worker と D1 を立てて流す

## 2026-11-02 作ったものの置き場をリポジトリの private/ にする

## 2026-11-02 「追記だけ」と「消す」の決まり（025b）

- 答えの表は追記だけのまま、**消すときの 1 通りの書き換え**だけを DB の守りが通す: やめた参加者の答え・秒・日本語の訳を空にし、`erased` の印を付ける。行そのもの（誰の何番目の答えか・見せたもの・判定）は残す。印を外す書き換えや、ほかの欄も変える書き換えは断る
- 消したことは監査の記録に「消した」の 1 行（回・参加者の番号・空にした行の数）だけを足す。答えの中身は監査の記録に入れないので、消しても連鎖はそのまま確かめられる
- 消した参加者の答えは、書き出し（answers.csv）に出さず、それ以降は受け付けない
- リセットは、テナントごとに監査の記録の連鎖を新しく始める（c1 → c2 …）。古い連鎖は消さずにとっておき、確かめる API はテナントの全部の連鎖を確かめる。ほかのテナントの連鎖は変わらない
- 行を丸ごと消す方法は採らなかった。番号が抜けると「誰かが消した」のか「やめた人の分を消した」のかが記録から分からなくなるため

## 2026-11-02 正式な取り出しのプロンプト（021）

仮版（`extract.ts`）は残し、正式版を `src/shared/extract/rules.ts` にゼロから書いた。変更のたびのフックは正式版で測る。

- 元の文に行番号を付けて渡し、決まりごとに「どこから」（根拠の言葉と行の範囲）を返させる。行番号がずれても、言葉から行を探し直す。見つからなければ found を false にして残す（黙って捨てない）
- 1 つの決まり = 1 つの行動。文の中の並びは行動ごとに分け、「〜せずに〜する」は dont と do に分ける。表・点検表の決まりは中身を写さず、「手元の✓」の型の印（checklist）を付ける
- 決まりを広げない（対象・場所・条件は元の文のとおり）
- 会社が主語の決まりは 2 通り: 作業のさせ方は作業員の行動に言い換えて印（reworded）を付け、賃金・休み・時間など会社が働く人に守ることは主語を会社のままにする
- 理由は 2 種類に分ける: 元の文に理由の言葉があるもの（stated）と、文からはっきり分かる危険（stated でない）。stated でない理由をカードに使うと「AI 下書き」に落ちる（035）。理由を元の文にあるものだけに絞ると、20 項目の漏れが増えた（理由の漏れ）ため、この形にした

- 調整では、20 項目の答えの中身はプロンプトに入れていない（種類ごとの数と、取りこぼした項目の元の文だけを見て、一般的な書き方に直した）。テストで、答えの文がプロンプトに無いことを確かめる

## 035 「AI 下書き」の判定

- 落とす条件は 2 つ: ① 元の文に無い理由（取り出しで stated でなかった理由・作成で AI が足した理由。文に ai の印が付く） ② 守ること・理由の文に、元の文の抜き出しに無い数字がある
- 数字は全角と半角をそろえて、決まりと理由の抜き出しの言葉と突き合わせる。抜き出しが手元に無い保存（画面から直接の保存・人の直し）では ① だけを見る
- 落ちたカードは「AI 下書き」の状態で保存し、監査の記録に ai_draft の 1 行（どの文がなぜ）を残す。人が直しても AI が書いた文が残っていれば AI 下書きのまま
