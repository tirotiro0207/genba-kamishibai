# UI と機能の直しの記録

作者と画面を 1 つずつ見ながら直した記録。1 件ごとに「どの画面・何を直した・なぜ・作者の好み」を残す。
好みは次の画面を直すときにも当てはめる（下の「好みのまとめ」に寄せる）。

## 前提（11/5 作者と確認）

- 画面は 2 つの側に分かれる → 発信する側（作者・監修者・教育担当）と、受け取る側（新入社員・現場の社員）
- 受け取る側は今も 1 ページ（`#/t/<テナント>/read`）
- 発信する側は今は画面が 10 ほどに分かれている（make・queue・card・route・fix・pose・fold・sign・issue・audit）
- 直しは発信する側から始める。最初はページを開いたときの入口（今は PIN の 2 段）

## 好みのまとめ

- 入口でいきなり PIN を聞かない。まず「誰として入るか」を選ばせる（会社の名前で入る / ゲスト）
- 会社の名前は「@ のあと」に打つ。SNS のユーザー名と同じ形で、英小文字だけ
- 選ぶ道は 2 択まで。上が本命（会社で入る）、下が「または」で区切ったゲスト
- 入口の後ろは、正方形の顔のカードが行ごとに右・左と交互に流れる。カードはときどきくるんと裏返り、別の人になる
- キャラクターは職業のかぶり物・髪形・目・まつ毛・口などをいろいろ混ぜる。かぶらない人もいる（キャラはあとで作者が手を入れる）
- カードは白い地で、黒い線の部分だけに色を付ける（作者が「元の白の状態」と呼ぶ形）。色はカードごとに乱数
- 1 枚の中は単色。目も線と同じ色にする（黒い所を残さない）
- 色は系統（ピンク・赤・橙・黄・黄緑・緑・青緑・青・藍・紫）ごとに同じ数。作者が渡した色は「混ぜる」ためで、その系統を多くする意味ではない
- 蛍光の色・明るすぎる色は使わない（白い地で線が見づらい。特に黄緑と蛍光の水色）
- 隣どうしは同じ色だけでなく、同じ系統（薄いピンクと濃いピンク）も、距離の近い色も並べない。同じ行に同じ系統をそろえない
- 入口の背景は黒。薄い黒の幕をかけ、その上に白い文字のフォーム
- 顔のカードの背景は入る前の画面の標準。PIN の画面にも敷く
- 入る前の画面のフォームは、画面の上ではなく真ん中に置く
- ブラウザの標準の部品（選ぶ欄の白い一覧など）は、暗い半透明の欄と合わないので使わない。同じテイスト（暗い半透明・ぼかし・細い縁）で作る
- 試して戻した形: 地を #E4F1F4・文字を黒・カードの白を透かす（直し 3）。白を透かすと重なりの後ろの髪や線が透けて見えた。白で描いて固めてから白をくり抜く形も試したが、作者の判断で黒い背景の形に戻した
