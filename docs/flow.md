# 今の仕組み

元の文がカードになり、新入社員に届くまでを【前】【中】【後】の段に分け、1 行 1 段で → でつなぐ。行の終わりの（）はマスの番号。まだ無い段は「（まだ）」と書く。作った順の記録は `docs/build-log.md`、作業の表は `docs/plan.md`。

## 【前】 元の文を入れる

→ テナントを選ぶ。練習用・架空の会社・会社の 3 つで、会社は PIN が要り、テナントをまたいで読めない（009）
→ 会社の資料は、そのテナント専用の非公開の置き場に入れる（031a）
→ 文を貼るか PDF を上げる。PDF はページの画像と行番号付きの文字にする。文字は PDF の文字の層から読み、層の無いページだけ Claude が読む。いまは手元のスクリプトで行い、画面の添付は置き場に入れるだけ（031b・032）
→ 夜間に資料を 1 ページずつ仕分ける。問いは「作業員が守る決まりがあるか」だけで、カードにする／しないと理由を Managed Agents が返し、ページごとの進み具合と答えを D1 に置く。止めて走らせ直すと続きから（022・023・024）
→ 会期前の見込みの一覧は仕分けに渡さず、仕分けが済んでから照合だけに使い、一致・不一致のページを出す。一覧と結果の表はリポジトリの外（024）
→ Claude が文から決まり（やること・やらないこと・なぜ）を、元の文の位置つきで取り出す。試験で分かった弱点（補足が近くに無い・なぜが元の文に無い など）と直したことは lessons-extraction.md にある（021・114）
→ 取り出しのプロンプトを変えるたびに調整用の 20 項目で測り、数を履歴に残す。採点の判定の崩れをコードが直したら、直す前の数と直しの 1 件ずつを残す（003b・120）
→ 作者が取り出した決まりを見て、カードにするものを OK する（033）。会社のテナントは、先に PIN で入る（009・038）
→ OK した項目を 1 つずつ「カードにする」で未承認の下書きにする。言い換えた項目などは「監修者に確認」の印と理由を付けて作り、カードの画面に出す。輪 1〜8 は会社のテナントでこの流れで作った。元の文に理由が無い輪 8 は、AI が理由を書いて AI 下書きになる（034a・038・039・054・055）

## 【中】 カードを作って確かめる

→ OK した 1 項目をカードの文（守ること・元の文の理由・元の文に無い理由は AI の印）に割り付ける（019・034a）
→ 先に Claude（Opus 5.5）が脚本を書く。決まりが働くきっかけ（異常など）を描ける物でどう見せるか、コマごとに誰が何をして見る人が何を分かるか、「なぜ」をどのコマで見せるか、読み違えそうなこと。描ける部品で見せられなければ足りない物を書く（11/5）
→ その脚本どおりに、Claude が人形の動きのキーフレームと、部品ごとの経路（どの文から・なぜそう描いたか）を数字で書く。動きのキーフレームは Opus 5.5。Sonnet の関節の角度は仮の流れだけ（005・034a）
→ 人形と部品を SVG から PNG のコマにする。人形は作者のスケッチに合わせた形（006・015・016a・117）
→ 絵の作り方の試しは、API を使わずに手元で動く SVG を動画にしてコマを切り出して回す（118）
→ 確かめる AI の伝わる率が赤なら、どう読まれたかを渡して作り直す。上限は用途ごと。いまは手元のスクリプトから流し、作る画面からはまだ呼ばない（034b）
→ 確かめる AI の正式版は作った側と別のエージェントで、文を見ずにコマを順に見て新入社員の役で答え、カードの文 1 つずつと照らして伝わる率（緑 80 以上・黄 60〜79・赤 60 未満、危ない読み違いは赤）を出す。カードの画面の「確かめる AI に見せる」から、サーバーが呼ぶ（047）
→ 呼び出しは全部、費用つきで記録し、用途ごとに費用の上限で止める（002・002b）
→ 元の文の位置と作成の中身は、未承認の下書きとして監査の記録に残る（020）
→ どの絵を見て・何点で・なぜかの証拠を監査の記録 ③ に残す。今の版に証拠が無いカードは「確認待ち」のまま、画面でもサーバーでも OK できない（047）
→ 帯は緑・黄・赤の 3 色だけ。危ない行為をしてよいと読める絵は赤い「危険」の印が絵の外に出て、直して確かめ直すまで OK も署名もできない。作る側の画面の上には「危ない読み違い ○枚・1 枚 ○分・伝わる率」をいつも出す（048）
→ 監修者が直したいコマの部分を指かマウスで枠で囲み、「ここをこうしたい」を書くか話して、文字を確かめてから送る。依頼は監査の記録 ④ に残る（044a）
→ 「この 1 枚を作り直す」で、枠に入った部品（人は関節の角度、小物は位置と大きさ）だけをそのコマで作り直し、版を上げて確認待ちに戻す。人数・役・小物の並びは変えないので、部品 → 文 → 元の文の経路は保たれる。1 枚 5 回まで（044b）
→ 監修者が AI に頼まず、絵の部品（人・時計・小物）を 1 つずつ選んでつまみで動かすと、角度と位置がその場で絵と JSON に出て、保存すると版が上がる。経路は保たれる（091）
→ 監修者が直すと、直した欄・前・後・直した人（役割のしるしから）・日時・理由が監査の記録 ④ に 1 件ずつ残る。何も変えない直しは増えず、理由の無い直しは断る（050）
→ 確認待ちのカードは赤 → 黄 → まだ確かめていない → 緑の順に並ぶ。監修者は夜間の仕分けの「する／しない」を理由つきで入れ替えられ、最初の AI の答えと入れ替えた人・時刻が残る（061）
→ 夜間に、仕分けで「する」のページから 1 ページ K 枚まで、取り出し → 下書き → 確かめる AI に通して確認待ちに入れる。全部未承認で、赤は列の先頭。止めて走らせ直すと続きから。10 枚の試しは全部確認待ちに入った（062）
→ 一括（約 120 枚）は、API で流す前に、Claude を呼ぶところだけを claude -p に差し替えた同じプログラムで通す。プログラムを通るので、プロンプトだけでなくプログラムの不具合も API の費用を使わずに見つかる（123 枚で 8 件、3 件を直した。dry-run-063.md）。そのあと API で 1 本で流す（まだ・063）

## 【後】 署名して届ける

→ 監修者 2 名・教育担当・新入社員・作者の役で入る。カードを止められるのは監修者だけ（030b）
→ 監修者が経路の画面で、絵の部品をタップして元の文の該当箇所（資料のページと行、話した言葉の字の範囲）が光るのと、なぜそう描いたかを確かめる（053）
→ 監修者が OK のカードのその版に署名すると、版・日付・中身のハッシュと、開いてから署名までの分数が監査の記録 ⑤ に残る。署名のあとに中身を書き換えると、ハッシュが合わないと分かる（051a）
→ 監修者が署名の画面で、タブレットとスマホは指で名前を書き、パソコンは電子印鑑（役と名前と日付。名前は環境変数から、無ければ空欄）を押して署名する。署名の絵の PNG のハッシュも ⑤ に残り、「未承認の下書き」の帯が消える（051b）
→ サーバーが、署名の無い・停止した・署名のあとに中身が変わったカードを新入社員に配らない。同じ監修者の署名は 1 日 20 枚までで、21 枚目は断る（052）
→ 会社のテナントは、PIN で入ったうえで役割の PIN でも入る。役割のしるしが無いと、役割で入る口のほかは全部断る（052b）。発行・署名・監査の画面も、しるしが無ければ同じ 2 段を出す（088）
→ 新入社員は会社のテナントの PIN と新入社員の PIN で入り、画面がカードを見るたびに見た印を送る（人は区別せず、役割と端末の単位）。監修者が署名済みを理由つき（必須）で止めると新入社員から消え、見た人の一覧と、版と署名の日付つきの回収の知らせが発行の画面に出る。毎週、署名済みから乱数で 2 枚を選び（種を記録）、署名していない監修者が見直す（088）
→ 新入社員は署名済みのカードだけを見る。経路は見せない（028）
→ カードを紙芝居のように 1 枚ずつ送る。画面・タブ・カードの切り替えは絵を抜くように 0.35 秒で動き、コマ送りはカードの動きの JSON をコマの間だけ再生する。「動きを減らす」設定では動かさない（076a）
→ 抜く紙は少し持ち上がって影が濃くなり、引っかかってから速く抜ける。下の画面は影から明るくなり、続けて押すと紙が重なって動く（076b）
→ 監修者と教育担当が、カードごとの記録（元の文 → 作成 → 確かめ → 人の直し → 署名）を画面で追う（041）
→ 新入社員の答えを回答の記録アプリで記録・採点し、名前を消して CSV に書き出す（011・012・025）
→ 仮の読み手 24 人（サブエージェント）に、文字の無い絵だけを見せて意味を答えさせ、判定役が守ること・なぜに照らして判定し、コードが輪 × 読み手の伝わる率を数える。輪 1〜5 で 1 回、輪 1〜8 で 1 回回した。2 回目は同じ読み手に資料の元の文も読ませ、参考として並べた（027・045・057）
→ 折りたたみの画面で、カードの元のページが積み重なって字数のカウンターが上がり、1 枚・0 字にたたまれるのを見せる。ページの中身は出さない。字数は空白を除き、スクリプト（scripts/fold-count.ts）と同じ数え方（081）
→ 署名済みのカードを、コマごとに版と日付入りの PNG・SVG に書き出す。帯は絵の下（絵の面の外）。署名のあとに中身が変わったカードは書き出さない。置き場は git の外。架空の会社の署名済み 10 枚で通しで流して 35 コマが出た（077）
→ 公開デモの架空の会社（元の文は demo/）の 10 枚は、スクリプトが手元の Worker の API を順に呼び、取り出し → OK → 作成（○× の組は場面つき）→ 確かめる AI → 署名 → 組を結ぶ、で作る（093a）
→ ほかの道具（Claude のアプリなど）からは MCP（/mcp/<テナント>）で「この資料をカードに」と頼める。会社ごとの鍵で入り（架空の会社だけ鍵なし）、画面と同じ流れで未承認の下書きまで作る。署名の呼び出しは断る（092）
→ 用語表の言葉と、人が直した前と後の言い方を、会社の言葉（呼び方・言い換え・使わない言い方）としてテナントごとに積む（085）
→ 本番は、手元と分けた DB と置き場で公開 URL に出す。練習用と架空の会社は誰でも開き、会社のテナントは PIN で入る（028b）
→ 公開 URL の入口は架空の会社だけ。「完成品を見る」で署名済みの 10 枚を、「その場で作る」で入れた文から 1 枚を作る（同じ IP から 1 日 3 回まで）（093b）
→ 公開デモで、見る人も「時間を計って答える」「絵だけで答える」を試せる。答えると決まりの文が出て、新入社員の匿名の結果と並ぶ。見る人の答えは送らない（094。新入社員の結果は、本物が入るまで「仮の数字」と出す）
→ 作る過程は、作業の表から進み具合の画面（進路図と日ごとのマス）に出す（109・115・116・119）
